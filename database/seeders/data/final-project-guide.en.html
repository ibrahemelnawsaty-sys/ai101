02

What is required of you

What must your project include?

  • An idea that solves a real problemYou know who faces this problem, and you can explain it in two sentences.
  • An AI technique at its coreUse at least one of the things we learned: Python and data, computer vision, language processing, or generative AI and agents. Its role in the solution must be essential.
  • A web page that a non-programmer can useA page published on GitHub Pages⁠, which anyone can open and try without installing anything or reading a long explanation.
  • A project that actually worksYou demonstrate it live in front of the audience, not just screenshots.
  • Work that you builtYou can explain every part of it: what goes in, what comes out, and why you chose this technique.
  • Security and privacyNo API keys in the code or in the repository, and no one's personal data without their permission.

What must you submit?

Six deliverables in this order. The final submission deadline is Wednesday, 30 September 2026

1. Project name

A short, clear name that expresses your idea, such as “Tammeni (طمني)” or “Wazen (وازن)”.

  • In Arabic or English.
  • The same name on the page, in the repository and in the presentation.

2. Project description

A paragraph of two or three lines: what the problem is, who the user is, and how AI solves it.

  • Put the same description at the top of your README⁠.

3. Link to the project repository on GitHub

A public repository containing the code and a README⁠ file, with a link like:github.com/sara-ali/my-ai-project

  • The README explains the problem, the solution and how to run it.
  • No API keys or personal data.
  • The steps for uploading and copying the link are in the “Uploading the project to GitHub” section.

4. Project link

The link to your page on GitHub Pages⁠, which opens without signing in, like:sara-ali.github.io/my-ai-project

  • Open it from another browser and from your phone before you submit.
  • The publishing steps are in the “Publishing on GitHub Pages” section.

5. Project logo

A clear image in PNG⁠ format, preferably square with a transparent background.

  • Design it with any design tool you know.
  • Put it on your page and on the first slide of your presentation.
  • Do not use another organization's logo or a copyrighted image.

6. Presentation

A maximum of 10 slides to present your project at the closing ceremony.

  • Put your project link on the last slide.

Suggested order for the ten slides

  1. Title and your name
  2. The problem
  3. Who is the user?
  4. The solution idea
  5. How AI works in it
  6. Live demo of the project
  7. Results and testing
  8. The project's limits and where it goes wrong
  9. What I learned and next steps
  10. Thank you, and your project link

06

The two paths and the tools

Two ways AI can work inside a page on GitHub Pages⁠, and each tool has a link and a QR

Why two paths? GitHub Pages publishes static pages only (HTML, CSS and JavaScript⁠): it doesn't run Python, and it can't hide an API⁠ key. So the AI in your page works in one of two ways:

Path One: a ready-made model via Gemini API

Your page sends the text to Gemini and displays the reply. It suits you if your idea is:

  • Generating, summarizing or analyzing text
  • Extracting information from text
  • A smart assistant with a specific style

Path Two: your own model with Teachable Machine

A model you train yourself that runs inside the browser without a key. It suits you if your idea is:

  • Classifying images with the camera or by uploading a picture
  • Recognizing sounds or words
  • Recognizing body poses
1

Path One: a ready-made model via Gemini API

A free key from AI Studio⁠, and a page that asks the user for the key when it is used.

Google AI Studio

Key for Gemini APIReady-made model

This is where you get your free Gemini API key, try out the prompt and the system prompt before you write the code, and ask Gemini to write your page's code for you.

Get a free key→Test the prompt in AI Studio→Ask for the page code→Upload it to GitHub→Publish it with GitHub Pages
Why choose it
  • Free, no card needed: Google documentation states that using AI Studio is free unless you link a paid API key.
  • The free models are the Flash and Flash-Lite⁠ families, while Pro models are paid.
  • You can try your whole idea in the chat before you build the page.
Watch out
  • GitHub Pages can't hide the key: anything on the page can be read by the visitor. So don't write the key in the code or upload it to GitHub⁠, and let your page ask the user for it when it is used. (The Google documentation itself warns against putting the key in web code or in Git⁠.)
  • Anyone who opens your link without a key will see the page, but the AI won't work for them. On presentation day you paste your own key; mention this in the README⁠.
  • Use a personal Google account. University and organization accounts may be restricted by their administrator.
  • Free-tier data may be used to improve Google⁠ products, so do not enter personal or confidential data.
Scan the code to openOpen the platformaistudio.google.com

Path One steps

  1. From aistudio.google.com, create a free key from Get API key.
  2. Try your idea in the chat: write the system prompt, and try real examples until it gives you the result you want.
  3. Ask Gemini to write the page for you using the ready-made prompt below (edit what is between the brackets), and save the output in a file named index.html.
  4. Open the file in your browser, paste your key, and try it. If you get an error about the model name, copy the model name from AI Studio and ask for it to be corrected.
  5. Upload index.html to your repository and publish it using the steps in the next section.

A ready-made prompt to ask for your page's code from Gemini

Ready-made prompt to copy
Write me a complete web page in a single file named index.html, in Arabic and with a right-to-left direction, that works on GitHub Pages without any server.
The page includes:
- A field where the user pastes their own Gemini API key. Do not write any key inside the code, and do not store the key in the browser.
- A field where the user types: [write here what the user enters in your project, such as: the lesson text]
- A button that sends the text to the Gemini API directly from the browser, with the following system prompt: [paste here the system prompt you tested in AI Studio]
- An area that displays the reply neatly, and a clear message if an error occurs.
Use a Flash model from the free tier, and explain to me with Arabic comments what each part does.
2

Path Two: your own model with Teachable Machine

You train it without code, and get ready-made JavaScript code that runs it inside your page.

Teachable Machine

No-code training

A tool from Google in which you train a model to recognize images, sounds or poses directly in the browser with no code, then get ready-made JavaScript code that runs your model inside your page.

Train the model→Export it with a link→Paste the code into index.html→Upload it to GitHub→Publish it with GitHub Pages
Why choose it
  • The model runs inside the visitor's browser with no key and no server, so your link works for anyone who opens it.
  • Google publishes this ready-made code in the teachablemachine-community repository on GitHub⁠, and it is the same code you see when you export the model.
Watch out
  • The model is only as good as your examples: each class needs many varied examples (lighting, angles and backgrounds).
  • Test it with examples it did not see during training, and say in the presentation where it goes wrong.
  • The camera needs the visitor's permission, and it works on GitHub Pages because its link is secure (https⁠).
  • Do not use pictures of people without their permission.
Scan the code to openOpen the platformteachablemachine.withgoogle.com

Path Two steps

  1. From teachablemachine.withgoogle.com, click Get Started and choose the project type: images (Image⁠), sounds (Audio⁠) or poses (Pose⁠).
  2. Create a class (Class⁠) for each result you want, and add many varied examples to each class, using the camera or by uploading images.
  3. Click Train Model, then try the model in the preview window.
  4. Click Export Model, choose Tensorflow.js, then upload the model (Upload⁠) to get your model's link, and copy the ready-made JavaScript code.
  5. Paste the code into the file index.html, and adjust the look: an Arabic title and an explanation for the user. (You can ask Gemini to make the page look nicer, as long as it does not change the model link.)
  6. Upload the file to your repository and publish it using the steps in the next section.

Button names may change slightly in these tools' interfaces, but the idea stays the same.

Warnings before you start

Keys for the API

Anything on a GitHub Pages page can be read by the visitor. So don't write the key in the code or upload it to GitHub⁠, and let the page ask the user for it. If your key appears in a public repository, delete it from AI Studio and create a new one.

Your data and other people's data

Free-tier data at Google may be used to improve its products. Do not enter personal or confidential names, numbers or files.

Free quotas are limited

Test your project early and don't wait for presentation day. Prepare screenshots or a short video as a backup.

Your personal account

Use a personal account for the tools. University and organization accounts may block some services.

07

Uploading the project to GitHub

A public repository containing your project files; its link is the second deliverable

  1. 1

    Create an account on GitHub

    From github.com, click Sign up; the account is free. Choose a clear username in English, because it appears in your project links.

    Output: an account on GitHub
  2. 2

    Create a new public repository

    Click New, type the repository name in English without spaces (such as my-ai-project), choose Public, enable Add a README file, then Create repository.

    Output: a public repository
  3. 3

    Upload your project files

    Inside the repository, click Add file then Upload files. Drag your files or click choose your files, write a short description in Commit message (for example: Upload the first version), then Commit changes. Make sure the main page is named exactly index.html, and that it is at the top level of the repository, not inside a folder. A single file can be up to 25 MiB when uploading from the browser.

    Output: your files in the repository
  4. 4

    Make sure the repository is public (Public⁠)

    Next to the repository name, the word Public appears. If Private appears: click Settings, scroll down to the Danger Zone section at the bottom of the page, click Change visibility next to Change repository visibility, and choose Public. Then confirm the repository name, click I have read and understand these effects, then Make this repository public.

    Output: a repository everyone can see
  5. 5

    Copy the repository link

    Open the repository's main page and copy the link from the browser's address bar. It looks like https://github.com/sara-ali/my-ai-project . This is the link for the second deliverable, which you submit. To make sure it is public: open it in a private window (Incognito⁠) without signing in; you must be able to see the code.

    Output: the repository link for submission
08

Publishing on GitHub Pages step by step

From the same repository you get your page link, which is the first deliverable

  1. 1

    Open the publishing settings

    At the top of the repository, click Settings, then in the sidebar Pages (under the section Code and automation⁠).

    Output: the settings page for Pages
  2. 2

    Choose the publishing source

    Under Build and deployment, set Source: Deploy from a branch. Then choose the branch main and the folder / (root), and click Save.

    Output: publishing has started
  3. 3

    Wait and copy your page link

    Publishing may take up to 10 minutes. After that, your site link appears at the top of the Pages⁠ page. For example: if your username is sara-ali and the repository name is my-ai-project, the link becomes https://sara-ali.github.io/my-ai-project/ . This is the link for the first deliverable. Open it from your phone and from another browser.

    Output: your project link for submission
  4. 4

    Edit and update

    Any file you upload or edit in the repository is published automatically, and it may take up to 10 minutes to appear. So don't make edits right before the presentation.

    Output: an updated version
  5. 5

    Complete the README

    Edit the README file in the repository: put your page link and your project description in it, using the ready-made template in the Submission section.

    Output: a repository ready for submission

If your page does not appear

A 404 page appears

Make sure the file name index.html is in lowercase letters and that it is at the top level of the repository, then wait a few minutes and refresh the page.

The README file appears instead of your page

GitHub Pages shows README if it does not find index.html. Rename your page to index.html⁠.

No option for Pages

Make sure the repository is public (Public⁠), and that you open Settings from inside the repository itself.

A Python app

GitHub Pages doesn't run Python, so Streamlit and Gradio apps can't be published on it. Use Colab only for experimenting and learning, and make your published version a web page.
