## درس مدفوع الثمن — 9 سبتمبر 2026

كان هذا الملف يحوي إجراء نشر من تأليفي، مكتوبًا دون قراءة الإجراء الذي كان يعمل
أصلًا في `RUNBOOK-first-deploy.md`. اتُّبع، **فعاد الإنتاج 500 على كل مسار** بما فيها
`/robots.txt`.

ثلاثة أخطاء فيه، تُسجَّل هنا حتى لا تتكرّر:

| الخطأ | الصواب |
|---|---|
| أمر بـ `php artisan config:cache` | **الإجراء العامل لا يشغّله.** يبني `view` و`route` فقط بعد `optimize:clear`، ويترك الإعدادات تُقرأ حيّة |
| أمر بـ `rsync --delete` إلى `public_html/build/` | **الإجراء العامل لا ينسخ أصولًا إطلاقًا.** جذر الويب يقرأ من `$APP/public`، و`--delete` قد يُفسد رابطًا رمزيًّا |
| بدأ بـ `git checkout` لفرع عمل | الخادم يتبع `main` عبر `git checkout -B main origin/main` |

**القاعدة المستخلَصة:** لا تُضِف إلى إجراء ناجح خطوةً لا يحتاجها. كل خطوة زائدة
خطر بلا مقابل، والخطر هنا كلّف الموقع توقّفًا كاملًا.

## أولًا · قبل أي نشر — نقطة الرجوع

```sh
# على جهازك: وسم ما هو منشور الآن
git tag -a deploy-$(date +%Y%m%d-%H%M) -m "الإنتاج قبل النشر"
git push origin --tags
```

```sh
# على الخادم: نسخة قاعدة البيانات — إلزامية لا اختيارية
mysqldump -u "$DB_USER" -p "$DB_NAME" \
  | gzip > "$HOME/backups/db/athar-$(date +%Y%m%d-%H%M%S).sql.gz"
```

صفحة الهبوط تقرأ: `cohorts` · `programs` · `weeks` · `sessions` · `landing_settings`.
تأكّد أن ملف النسخة موجود فعلًا وحجمه غير صفر قبل المتابعة.

## ثانيًا · النشر

اتبع `deploy/RUNBOOK-first-deploy.md` قسم «النشر التالي». لا تكتب إجراءً منافسًا.

إن أضاف النشر ترحيلًا — كما تفعل دفعة `profiles.job_title` — أضف بعده:

```sh
php artisan migrate --force
php artisan migrate:status | tail -5
```

الترحيل يضيف عمودًا نصّيًّا يقبل الفراغ، ولا يحذف شيئًا ولا يغيّر عمودًا قائمًا،
و`down()` مُختبَر على قاعدة فعلية.

## ثالثًا · بيانات الإنتاج — وهي أصل أربعة أعطاب مرئية

قاعدة الإنتاج تحمل **بذرة عرض توضيحي**، لا محتوى أدخله مدير:

| ما يراه الزائر | السبب |
|---|---|
| أسابيع بتواريخ منقضية | البذرة تحسب التواريخ نسبةً إلى «اليوم» وتضعها في الماضي عمدًا |
| «بلا جلسات مباشرة» أربع مرات | جدول `sessions` فارغ |
| «0 من 60 مقعدًا محجوزة» | `seats_taken = 0` |
| التسجيل مغلق | `status = running` و`registration_closes_at` في الماضي |

> ⛔️ **لا تشغّل `migrate:fresh` ولا `db:seed` على الإنتاج.** الأولى تحذف كل شيء،
> والثانية تُعيد حقن البيانات التجريبية نفسها التي تريد التخلص منها.

الطريق الصحيح من لوحة الإدارة، بلا أمر واحد على قاعدة البيانات:

1. **دفعة جديدة** بحالة `open`، بتواريخ الدليل الرسمي، و`registration_closes_at`
   في المستقبل، وسعة صحيحة.
2. **أسابيعها وجلساتها** — هذا وحده يُسقط «بلا جلسات مباشرة»، ويملأ `sessions_total`
   الذي كان صفرًا فأنتج `NaN`.
3. **مهام الدفعة** — عددها يظهر في المحاكي بعد إصلاح `BR-11`.
4. **حسابا المدرّبَين**: م. إبراهيم النوساني · م. أحمد سامي — الأسماء كما في الدليل
   الرسمي. سجّلهما في الدفعة بدور `trainer`، وأكمل المسمّى والنبذة والصورة.
5. **أرشفة الدفعة القديمة** إلى `completed` حتى لا تتنافس على الظهور.

## رابعًا · التحقق — لا يُبلَّغ عن نجاح قبل تشغيل كل سطر

```sh
# الصفحة تستجيب أصلًا
curl -s -o /dev/null -w "home %{http_code}\n" https://ai.wareed.vip/

# لا NaN ولا نائب خامّ
curl -s https://ai.wareed.vip/ | grep -c 'NaN'
curl -s https://ai.wareed.vip/ | grep -cE ':count|:sessions|:min'

# البرنامج ليس مجانيًا — والادّعاء يُقرأ آليًّا
curl -s https://ai.wareed.vip/ | grep -o 'isAccessibleForFree":[a-z]*'   # false

# وسم الوصف ليس فارغًا
curl -s https://ai.wareed.vip/ | grep -oE '<meta name="description" content="[^"]{5,}"'

# ملفّا الفهرسة
curl -s -o /dev/null -w "robots %{http_code}\n"  https://ai.wareed.vip/robots.txt
curl -s -o /dev/null -w "sitemap %{http_code}\n" https://ai.wareed.vip/sitemap.xml

# لا أيقونة فارغة
curl -s https://ai.wareed.vip/ | grep -c 'href="#i-"'
```

المتوقّع: `200` · `0` · `0` · `false` · وسم غير فارغ · `200` · `200` · `0`.

ثم **افتح الصفحة بعينك** على 360 و768 و1280 بكسل: العدّاد يتحرّك · الخط الزمني يعرض
تواريخ · قسم المدرّبين يظهر · بطاقة الشهادة لا تنقلب إلى وجه فارغ.

### السجلّات — بالاسم الصحيح

القناة الافتراضية `daily`، واللاحقة اسم التطبيق:

```sh
ls -la "$APP/storage/logs/"
grep -n "ERROR\|CRITICAL" "$APP/storage/logs/athar-$(date +%Y-%m-%d).log" | tail -15
```

**الملف `laravel.log` غير موجود على هذا الخادم ولن يوجد.** البحث عنه يعطي «الملف غير
موجود» على خادم سليم تمامًا، وهو إنذار كاذب أُطلق فعلًا في هذه الحادثة.

## خامسًا · التراجع

**حدّ زمني: إن لم تعُد `/` سليمة خلال عشر دقائق، ارجع. لا تُصلح على الإنتاج.**

```sh
cd "$APP"
git checkout -B main <الوسم أو الالتزام السابق>
php artisan optimize:clear && php artisan view:cache && php artisan route:cache
```

**لا `config:cache` هنا أيضًا.** التخزين المؤقت أثناء حالة مكسورة يُجمّد الكسر.

**ولا تتراجع عن الترحيل** إن كان عمودًا يقبل الفراغ: الكود القديم لا يتضرّر بوجوده،
و`migrate:rollback` مخاطرة بلا مقابل.

لاسترجاع قاعدة البيانات إن لزم:

```sh
gunzip < "$HOME/backups/db/<النسخة>.sql.gz" | mysql -u "$DB_USER" -p "$DB_NAME"
```

## ما لا يعالجه هذا الإجراء

بنود موقوفة على قرار من المركز، لا على تنفيذ:

- **`D-58`** موعد تسليم الشهادة في الخط الزمني — لا عمود في المخطّط يحمله.
- **`D-59`** بيانات المدرّبَين الناقصة: بريد · جوال · صورة.
- **طبقة الدفع** — الدليل يسعّر البرنامج بـ1,499 ريالًا ويقول «لا يُعتمد الحجز إلا بعد
  إتمام الدفع»، ولا مفهوم للمال في المنصة: لا سعر ولا عملة ولا ضريبة ولا فاتورة.
- **صفحة الشروط والأحكام فارغة** بينما التسجيل يُجبر على قبولها.
- **رقم السجل المدني غير مجموع** — وشهادة TVTC تصدر به وفق الدليل.
- **عدد المتدربين السابقين** — لا عمود ولا رقم موثّق.
